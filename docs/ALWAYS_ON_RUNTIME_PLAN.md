# SullyOS 持续运行方案（工作文档）

> 状态：方案已确认，开始实施。本文档记录目标、边界和实现顺序；未完成前不视为最终产品说明。

## 一、产品目标

SullyOS 不是只在用户打开聊天页面时工作的 App，而是一个可以持续运行的角色世界：

- 用户在设置中打开“持续运行”；
- SullyOS 尽可能长期在后台运行；
- 角色可以主动找用户聊天；
- 角色可以自行去彼方并产生事件；
- 任务、日程和主动活动继续调度；
- 用户切换到其他 App 或锁屏后，正在进行的活动尽量不中断；
- Android 杀进程或 WebView 被回收后，结果仍可恢复，不丢消息和事件。

“持续运行”不能承诺 Android 层面的绝对永生，但应通过 Foreground Service、原生调度、通知权限/电池设置引导，把可靠性做到平台允许的最高水平。

## 二、通知规则

### 常驻通知

持续运行开启后，唯一的常驻通知内容固定为：

```text
SullyOS 正在运行
```

不在常驻通知中添加技术说明、运行模式、电池优化提示或后台任务描述。

### 角色事件通知

其他通知只用于真实的角色事件，并采用角色化短文案：

```text
标题：阿澄
正文：刚刚去彼方了
```

```text
标题：阿澄
正文：给你发了一条消息
```

```text
标题：阿澄
正文：在彼方遇到了一件事
```

错误也不暴露技术术语，优先转成角色化短句，例如“刚才没能联系上你”。短时间内的多条事件需要合并，避免通知刷屏。

## 三、通知约定（已确认）

- 常驻通知固定为：`SullyOS 正在运行`；不附加技术说明或任务说明。
- 角色事件通知使用：`角色名 + 角色化短句`，例如“阿澄 / 给你发了一条消息”“阿澄 / 刚刚去彼方了”。
- 彼方和任务通知优先带名称预览，例如“阿澄 / 刚刚去了「雨夜车站」”“阿澄 / 完成了「整理房间」”；无名称时退化为通用短句。
- 工具请求保留角色化提示，例如“我想查点东西，点开继续”。
- 情绪同步、恢复过程、API 错误、原生任务状态不直接向用户展示技术文案。
- 角色通知只在确实有事件时显示；常驻通知与事件通知分离。

## 四、运行层次

```text
WebView / React UI
  ├── 设置和状态展示
  ├── 聊天、彼方、任务页面
  └── 与原生 Runtime 同步

Android Native Runtime
  ├── 常驻 Foreground Service
  ├── 主动消息调度
  ├── 彼方活动调度
  ├── 任务/日程调度
  ├── 网络重试和结果落库
  ├── 角色事件通知
  └── WebView 回收后的恢复扫描

Recovery Store
  ├── 未完成任务
  ├── 原始响应
  ├── 事件幂等键
  └── 恢复/重试状态
```

WebView 不应是持续运行的唯一执行载体；`setInterval` 只能作为前台 UI 辅助，不能承担后台世界的可靠调度。

## 四、开关语义

设置增加独立模块“持续运行”，不改变现有 UI/UX 风格。

打开后：

- 启动常驻 Foreground Service；
- 显示固定通知“ SullyOS 正在运行”；
- 开启主动消息、彼方活动、任务/日程后台调度；
- 允许正在进行的后台请求继续执行；
- 保留恢复机制作为兜底。

关闭后：

- 停止常驻服务和后台调度；
- 未完成任务和结果仍保留；
- 用户下次打开 APK 时执行恢复/补偿；
- 不删除历史数据。

## 五、调度策略

- 实时/长请求：Foreground Service；
- 延迟、周期和任务监督：WorkManager 或原生持久化调度；
- 服务器主动事件：优先使用推送，原生 Runtime 接收后落库并通知；
- 手机重启：扫描未完成任务，按幂等策略恢复，不无条件重放所有请求。

## 六、恢复和幂等

保活和恢复不是二选一：

- 保活：尽量让角色世界继续运行；
- 恢复：服务或 WebView 被杀后不丢数据。

所有可产生副作用的动作需要事件级幂等键：

```text
${chatJobId}:${actionType}:${actionIndex}
```

恢复时：

- 纯消息和卡片可以自动恢复；
- 备忘录、彼方事件、任务创建需要幂等落库；
- 外部副作用需要记录执行状态；
- 音乐动作恢复为待用户操作，不在后台自动播放；
- HTML 卡片恢复前重新经过安全清洗。

## 七、实施顺序

1. 将持续运行开关和 Runtime 状态持久化；
2. 把 Foreground Service 从“单次请求服务”扩展为“持续运行服务”；
3. 增加常驻通知，固定文案为“ SullyOS 正在运行”；
4. 将主动消息/彼方/任务调度迁移到原生可恢复队列；
5. 增加角色事件通知和通知合并；
6. 增加设置中的“持续运行”模块和权限引导；
7. 完善事件幂等和恢复；
8. 补充 Android/恢复/重复执行测试；
9. 构建并安装验证 APK。

## 八、明确不做

- 不承诺 Android 绝对不会杀进程；
- 不在常驻通知中写技术解释；
- 不让 WebView 永久承担后台调度；
- 不在后台无条件自动播放音乐；
- 不在恢复时无幂等地重复执行外部动作；
- 不改变 SullyOS 原有视觉风格。
